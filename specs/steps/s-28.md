# Step 28 — Dashboard UI (Next.js Financial Control Plane)

## Objective

Build the complete dashboard in `apps/frontend`: authenticated shell, executive overview, operations case list/detail with live timeline, risk view, recovery analytics, policy management, audit viewer, human-task inbox with approve/reject actions, and settings — consuming only the APIs from s-09…s-27.

## Why this step exists

Spec 00 §6 defines the killer experience: "The dashboard should feel like a financial control plane," with exact card sets and the case timeline demo moment; spec 01 §16 lists the eight pages; spec 03 §7 the data each shows. The frontend is observation-only (spec 02 §1) — it must never compute business state client-side beyond display formatting (₹ grouping).

## Requirement Coverage

- Spec 01 §16 pages list + cards/charts
- Spec 00 §6 three views incl. AI view numbers; case timeline layout
- Spec 03 §7 dashboard requirements (overview, funnel, intervention table, case detail fields)
- Spec 03 §11 "No provider secret in frontend"

## Prerequisites

- All backend APIs s-09…s-27; auth endpoints for login flow

## Requirements

1. Auth: login page → session cookie; middleware guards /dashboard routes; logout; role-aware UI (buttons hidden/disabled per matrix from s-09 — server-enforced regardless).
2. Pages (App Router):

```text
/login
/dashboard          overview cards (Revenue at Risk, Recovered, Recovery Rate, Recovery Cost,
                    Net Recovered, Active Cases, Escalations) + recovery-by-day chart + risk mix
/cases              filterable table (status, risk band/type, amount, age) w/ saved-filter chips
/cases/[id]         canonical detail: obligation summary, risk factors breakdown ("why at risk"),
                    AI decision card (diagnosis+confidence+actions), policy verdicts, workflow status,
                    actions ledger w/ attempt results, customer responses, outcome card, TIMELINE feed
/risk               open risks table by type/band w/ factor drill-down
/recovery           funnel viz + intervention performance table + channel/provider breakdowns
/policies           rule list, enable/disable, version history diff viewer (FINANCE+ editing)
/audit              admin audit search (ADMIN)
/tasks              human task inbox: pending/overdue badges, approve/reject modals (notes required on reject)
/settings           tenant profile, team mgmt (ADMIN), API keys (ADMIN), mock-mode banner when enabled
```

3. Case timeline component: virtualized chronological feed matching GET /cases/:id/timeline shape; auto-refresh via polling (30s) — websockets explicitly out of MVP scope.
4. Money rendering: integer minor units → ₹ formatting util (lakh/crore grouping), currency-aware.
5. Charts: lightweight lib (Recharts) — recovery/day area chart, funnel bar, intervention table w/ inline success-rate bars.
6. Loading/error/empty states standardized; optimistic updates ONLY for non-financial mutations (pause/resume); approvals always round-trip confirmed.
7. Accessibility pass (labels, focus states) + responsive to 1280px primary target.

## Technical Implementation

### Structure

```text
apps/frontend/src/
├── app/(auth)/login/page.tsx
├── app/(dashboard)/{dashboard,cases,cases/[id],risk,recovery,policies,audit,tasks,settings}/page.tsx
├── components/
│   ├── charts/ cards/ timeline/ tables/
│   └── cases/{decision-card,policy-verdict,actions-ledger,outcome-card,risk-factors}
├── lib/
│   ├── api.ts                 # typed fetch wrapper w/ error envelope handling + 401 redirect
│   ├── money.ts format.ts
│   └── rbac.ts                # mirror of server matrix for UX gating only
└── middleware.ts               # cookie guard
```

Data fetching: React Server Components for initial page loads + client components for interactive filters/timeline polling. No direct DB access from frontend ever.

### Demo polish hooks

`?demo=1` query param (dev/mock mode only): enlarges fonts on case timeline for screen-share; settings page surfaces simulator shortcuts linking to /demo endpoints (rendered only when MOCK_PROVIDERS=true).

## Data Model Changes

None (frontend consumes APIs exclusively).

## API Contracts Consumed

Full inventory table added to step PR description mapping every UI element → endpoint (traceability artifact). No frontend-created endpoints.

## State Transitions

UI reflects server state; control buttons map to pause/resume/stop/escalate/approve/reject endpoints with confirmation dialogs for financially-impactful ops (stop, reject).

## AI Behavior

Display-only. Decision card must render confidence as %, show fallback badge when status=FALLBACK_RULE_BASED, and surface policy rejections prominently (Policy Rejections counter lives in /recovery AI panel per spec 00 §6 AI view).

## Reliability

API failure → inline retry banners, not blank screens; polling tolerant to 409 races (refetch-on-conflict pattern).

## Security Considerations

No secrets/env besides NEXT_PUBLIC_API_URL; XSS-safe rendering of template variables (React default escaping; no dangerouslySetInnerHTML anywhere — lint enforced); session cookie handled by browser; CSRF posture inherited from SameSite=Lax + JSON POSTs.

## Observability

Client error boundary logs to console + optional endpoint later; Core Web Vitals budget noted (LCP <2.5s local).

## Tests

- Component tests (Vitest + Testing Library): money formatting (₹12,999 / ₹4,80,000 / ₹12.8L), RBAC button gating matrix, timeline ordering + enrichment badges, decision card fallback state, funnel math from fixture payload.
- Route-guard tests: unauthenticated redirect; role-restricted page 403 view.
- One Playwright smoke (headed-optional): login → dashboard cards render → open seeded case → timeline visible → approve pending task → status change reflected. Full E2E journey stays in s-32.
