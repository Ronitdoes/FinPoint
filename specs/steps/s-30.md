# Step 30 — Security Hardening & Compliance Verification

## Objective

Systematically verify and harden the full security surface against spec 03 §11 acceptance criteria: tenant isolation (incl. RLS evaluation), secret handling, PII minimization, webhook signature enforcement, RBAC completeness, rate limiting/abuse prevention, audit immutability, and dependency hygiene — producing a signed-off security checklist with evidence.

## Why this step exists

Security requirements are scattered across every step by design; this step consolidates verification into one auditable pass so nothing relies on "we were careful during s-XX." Financial systems get one chance at trust; the checklist-with-evidence format makes that verifiable by reviewers and future agents.

## Requirement Coverage

- Spec 03 §11 all eight acceptance criteria
- Spec 01 §22 security list (tenant isolation, RBAC, signatures, encrypted secrets, least-privilege creds, PII minimization, audit logs, rate limiting, CSRF)
- Spec 02 §14 security boundaries diagram — verified per boundary

## Prerequisites

- All feature steps; s-25 audit immutability already structural

## Requirements

1. Tenant isolation proof suite: automated cross-tenant probe tests for EVERY tenant-scoped endpoint (generated from route inventory): swapping ids in path/body/query must yield 404/empty — never 200-with-foreign-data. RLS evaluation ADR: document decision to rely on app-layer scoping + indexes at MVP vs enabling `CREATE POLICY` per table (recommendation: enable RLS on recovery_cases/payments/messages as defense-in-depth if connection pooling supports session vars — decide + record).
2. Secret sweep CI job: regex scan repo + built frontend bundle + docker context for key patterns (`sk_live|sk_test|whsec|rzp_|AKIA|BEGIN PRIVATE KEY`); fails build.
3. Log redaction verification: integration run with known-secret env values → assert zero occurrences across captured logs/traces/metric labels.
4. Rate-limit policy finalization per route class (webhooks 600/min/IP, auth 5/min, reads 120/min/key, /events 60/min, demo disabled-in-prod) + abuse rules: repeated 401 signature failures → temporary IP block (Redis).
5. CSRF posture review + document (SameSite=Lax + JSON-only POSTs; token approach deferred w/ rationale) or implement double-submit if any cookie-mutating form exists.
6. Dependency audit: `bun pm audit`-equivalent gate + lockfile diff policy; pin runtime base images by digest (used in s-33).
7. Least-privilege credentials doc per provider (separate read/write keys where supported; webhook-secret rotation runbook).
8. Produce docs/SECURITY-CHECKLIST.md mapping each §11 criterion → implementation → test file(s) → status.
