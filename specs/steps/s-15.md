# Step 15 — AI Governance: Cost Accounting, Evaluation Harness & Safety Tests

## Objective

Complete the AI control plane around the s-14 decision path: per-case cost ledger entries from token usage, decision quality evaluation harness with golden datasets, confidence-threshold policy hooks contract, prompt-version comparison tooling, and the adversarial test suite (invalid outputs, unsafe recommendations, policy violations, provider failures).

## Why this step exists

Spec 00 §9 defines AI economics metrics (AI Cost per Case, Cost per ₹ Recovered, Decision Acceptance Rate) and spec 01 §20 requires LLM token/latency instrumentation — numbers only matter if captured at source and comparable across prompt versions. Separating this from s-14 keeps the decision path shippable while governance reaches production rigor. This step is also where "the LLM cannot be trusted implicitly" gets proven by tests rather than asserted in docs.

## Requirement Coverage

- Spec 00 §9 AI metric set (acceptance rate, recommendation→execution rate, cost/case, cost/₹ recovered)
- Spec 02 §8 recovery cost model (LLM cost category)
- Spec 03 §9 SIMULATE_LLM_FAILURE (adversarial coverage)
- Spec 01 §23 AI-adjacent unit tests (decision schema, low confidence, malformed)

## Prerequisites

- s-14 (decision path + ai_decisions rows), s-05 (recovery_cost_entries)

## Requirements

1. Cost computation: price-table constant `{model: {input_per_1k_minor, output_per_1k_minor}}`; on each COMPLETED/FALLBACK decision write `recovery_cost_entries(category=LLM, amount=computed)` linked to case.
2. `GET /ai/decisions?case_id=` + `GET /ai/decisions/:id` read APIs (OPERATIONS+).
3. Evaluation harness `services/eval` (script workspace): golden-set runner that replays stored input_snapshots against current or specified prompt versions WITHOUT executing actions, producing a report:
   - schema-validity rate, action-distribution drift vs baseline version, mean confidence, mean latency, est. cost delta
4. Confidence hook contract: exported `requiresApproval(decision, surface): boolean` implementing MVP rule — consumed by policy engine s-16 and tested here.
5. Adversarial test suite codified (see Tests).
6. Prompt-change checklist doc: bump version → run eval harness → attach report to PR.

### Golden dataset format

```json
{ "case_ref": "golden/payment-failure-001",
  "input_snapshot": { "...": "s-13 context triple" },
  "expect": {
    "must_not_actions": ["OFFER_INCENTIVE"],
    "should_actions_any_of": [["RETRY_PAYMENT"],["SEND_WHATSAPP"]],
    "min_confidence": 0.5,
    "cause_one_of": ["insufficient_funds","stale_card","unknown"] } }
```

Harness output: JSON + markdown table; exit code non-zero on validity<95% or must_not violation → CI-able gate for prompt bumps.

### requiresApproval rule (v1)

```text
true  if any action ∈ {RETRY_PAYMENT, CREATE_PAYMENT_LINK, OFFER_INCENTIVE}
        AND diagnosis.confidence < 0.6
true  if OFFER_INCENTIVE regardless of confidence
false otherwise
```

Exact final matrix co-designed with s-16 rules; single implementation location HERE, imported THERE (no duplication).

## AI Behavior

This step adds the measurable guardrails:

- What AI is responsible for: nothing new (governance reads/validates).
- Not allowed: harness never executes actions; eval runs flagged purpose=EVAL and excluded from production analytics via metadata flag.
- Guardrails proven by tests below; fallback behavior re-verified under chaos flags.
- Cost consideration enforced: hard max_tokens already set; harness reports cost deltas so regressions visible pre-merge.
- Logging: eval runs log aggregate stats only.

## Reliability

Cost-entry write is transactional with decision insert (no orphan costs). Pricing unknown model → fail CLOSED (throw CONFIG error) rather than free decisions.

## Security Considerations

Decision snapshots may embed masked-but-sensitive aggregates; read APIs gated; snapshot inclusion admin-only by default.

## Observability

Metrics: `ai_cost_case_minor` histogram; `ai_requires_approval_total{result}`; eval harness prints summary (not part of runtime metrics).

## Tests (the adversarial suite — all required)

```text
 1. Valid output path                → row COMPLETED, cost entry written
 2. Invalid structured output        → INVALID_OUTPUT recorded, repair invoked once, then FALLBACK
 3. Low confidence (0.4) + RETRY     → requiresApproval=true
 4. High confidence (0.9) + EMAIL    → false
 5. Unsafe recommendation            → action outside surface subset injected by mock → rejected semantically
 6. Policy-violating suggestion      → incentive > cap → semantic rejection before policy layer
 7. Missing context fields           → CONTEXT_INVALID, no LLM call made
 8. LLM timeout                      → retry ×2 → FALLBACK_RULE_BASED; latency budget respected
 9. Provider 500s                    → circuit opens after threshold; subsequent calls skip network
10. Token accounting                 → usage parsed across provider shapes; cost math exact
11. Eval harness                     → golden-v1 passes on baseline prompt; tampered prompt fails must_not check
```
