# Step 33 — CI/CD & Deployment (Environments, Images, Release Pipeline)

## Objective

Deliver the deployment system: GitHub Actions pipeline (lint→typecheck→test pyramid→build→image publish→migrate-check→deploy gates), production Dockerfiles for API/worker/frontend, environment matrix (Local/Staging/Production) with config and secret strategy, migration execution policy, webhook endpoint configuration, and rollback procedure.

## Why this step exists

Spec 01 §26 specifies targets (Vercel for Next.js; AWS/Railway/Render for API+workers+Postgres+Redis+Redpanda; Docker for API/workers) and required CI stages (lint, typecheck, unit, integration, build, migration checks). Deployment must be implementation-ready: a future agent or operator follows this step and ships without improvisation.

## Requirement Coverage

- Spec 01 §26 deployment topology + CI checklist
- Spec 03 §10/§11 operational acceptance carried into prod configs
- Spec 02 §14 boundaries (credentials reach only adapters — verified in image builds)

## Prerequisites

- s-30 security jobs; s-32 e2e gate; s-08 metrics endpoints

## Requirements

1. Dockerfiles:
   - `apps/backend` + `services/worker`: multi-stage (bun install → prune dev → distroless-ish slim base pinned by digest), non-root user, healthcheck hitting /health, identical image for API & worker (entry differs) to cut build surface
   - `apps/frontend`: Next standalone output build; no build args carrying secrets (only NEXT_PUBLIC_*)
2. Compose profiles finalized (`dev`, `e2e`) documented vs production assumptions.
3. CI pipeline (`.github/workflows/ci.yml`) stages:

```text
setup(bun cache) → lint → check-types → unit → integration(compose services) →
security(sweep+probes) → build(images) → migrate:check(against ephemeral pg) →
e2e(full profile) → publish images(tagged sha+semver) → deploy-staging(gate: manual approval) → smoke(staging) 
```

4. Environments:
   - **Staging**: managed Postgres (+pooler, DIRECT_URL separate), Redis, Temporal Cloud OR self-host single-binary, Redpanda, API×2 replicas behind LB, worker pool (2), frontend on Vercel preview/staging project. MOCK_PROVIDERS=false with provider TEST keys; real webhooks registered to staging domains.
   - **Production**: same topology, HA choices documented (managed PG w/ PITR, Redis w/ persistence, Temporal namespace per env), secrets in platform secret store injected at runtime — never in images/env files committed.
5. Migration policy: migrations run as pre-deploy job (DIRECT_URL) with advisory lock (s-06); expand→contract pattern mandated for breaking changes; app version N compatible with schema N+1 during rolling deploys (documented rule).
6. Webhook configuration runbook: register Stripe/Razorpay/WhatsApp endpoints per env, store secrets in platform, rotation steps referencing s-30 runbook.
7. Rollback: images immutable by tag; `rollback` workflow redeploys previous tag AFTER verifying schema compatibility flag (migrations forward-only → rollback = previous APP version on current schema; DB point-in-time recovery documented as last resort with owner approval).
8. Cron inventory deployed: attribution sweeper (hourly), cost-completeness (daily), invoice reconciler + PTP expiry (daily), retention stub (monthly) — scheduled via worker process cron module or platform scheduler; table of jobs/schedules/idempotency in docs.

### Environment variable matrix (summary — full table in doc)

Every var from `.env.example` categorized: LOCAL-DEFAULT / STAGING(secret ref) / PROD(secret ref) + which component consumes it; MOCK_PROVIDERS forced false in staging/prod; demo routes asserted absent (startup self-check logs).

None.

## API Contracts

Infra-level: LB health checks → `/health`; readiness gating via `/ready`. Document expected probe intervals/timeouts.

## State Transitions

Deployment states tracked by pipeline (building→deploying→smoke-passed→live; rollback path) — documented, not modeled in DB.

## AI Behavior

Prod LLM key scoped/budgeted; model name pinned per env via AI_MODEL (staging may differ for cost); circuit-breaker thresholds reviewed under real latency profile.

## Reliability

Zero-downtime: API replicas roll; Temporal workers drain before termination (preStop sleep + poller shutdown from s-20); bus consumers commit-before-exit; migrations decoupled from app deploys.

## Security Considerations

Images non-root, digest-pinned; registry private; deploy credentials OIDC-scoped (no long-lived cloud keys in CI); secrets scan stage reused from s-30.

## Observability

Deploy events annotated into Grafana later (s-34 hook: annotation API noted); smoke = scripted journey-lite against staging post-deploy (subset of s-32 journeys tagged @smoke).

## Tests

Pipeline itself validated by running full flow against staging; rollback drill executed once and documented (required evidence). Image smoke: containers start with minimal env and fail LOUDLY with missing-required-config errors listing the missing keys.

- [ ] Rollback drill completed and documented
