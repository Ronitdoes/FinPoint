# Step 05 — Database Schema: Recovery Domain Entities

## Objective

Implement the recovery-side schema: normalized event store, revenue risks, recovery cases, AI decisions, recovery actions/attempts, workflow records, messages + deliveries, customer responses, promises-to-pay, human tasks, policy rules/versions/evaluations, audit logs, case events (timeline), recovery outcomes, cost entries, and the general idempotency-key store. Generate and apply the second migration.

## Why this step exists

This is the heart of the platform's state: `RecoveryCase` is the central object everything links to (spec 02 §3). Designing these tables now — with their uniqueness constraints and partial indexes — is what makes later guarantees ("a duplicate webhook must not create duplicate recovery cases", spec 01 §12) enforceable by the database instead of by hope.

## Requirement Coverage

- Spec 01 §5 remaining tables (revenue_risks … recovery_outcomes)
- Spec 02 §3 canonical recovery case; §4 state machine; §8 cost model; §9 attribution fields
- Spec 03 §4 recovery_cases / recovery_actions / audit_logs / recovery_outcomes fields
- Spec 01 §17 case timeline; §18 audit trail fields; §19 human_tasks
- Spec 01 §21 idempotency key format for financial actions

## Prerequisites

- s-04 (shared helpers/enums pattern established)

## Requirements

1. Schema files as below; all business tables tenant-scoped with audit timestamps.
2. Append-only tables (`events`, `audit_logs`, `case_events`, `workflow_events`, `message_delivery_events`) get no UPDATE paths in repositories (enforced in s-06).
3. Partial unique index preventing concurrent open cases for the same obligation.
4. Migration generated + applied.

### Tables

**events** (normalized internal event log — raw provider payload preserved)
- `id UUID PK`
- `source PROVIDER NOT NULL` | `'INTERNAL'` via enum extension `EVENT_SOURCE(STRIPE, RAZORPAY, INTERNAL)`
- `external_event_id TEXT NULL` — UNIQUE `(source, external_event_id)` where not null ← **webhook idempotency anchor**
- `type EVENT_TYPE NOT NULL` (domain taxonomy from s-03)
- `tenant_id FK NOT NULL`, `customer_id FK NULL`, `entity_type TEXT`, `entity_id TEXT`
- `raw_payload JSONB NOT NULL` (verbatim provider body), `payload JSONB NOT NULL` (normalized envelope payload)
- `correlation_id UUID NOT NULL`
- `status EVENT_STATUS(RECEIVED, PROCESSING, PROCESSED, FAILED) NOT NULL DEFAULT 'RECEIVED'`
- `received_at TIMESTAMPTZ NOT NULL DEFAULT now()`, `processed_at TIMESTAMPTZ`
- Index `(tenant_id, type, received_at DESC)`, `(status)` partial where status != PROCESSED

**revenue_risks**
- `id UUID PK`, `tenant_id FK NOT NULL`
- `customer_id FK NOT NULL`
- `risk_type RISK_TYPE enum NOT NULL`
- `subject_type TEXT NOT NULL` ('PAYMENT'|'CHECKOUT'|'INVOICE'), `subject_id UUID NOT NULL`
- `score INT NOT NULL CHECK (score BETWEEN 0 AND 100)` (rule-based v1)
- `band RISK_BAND enum NOT NULL` (LOW/MEDIUM/HIGH/CRITICAL)
- `factors JSONB NOT NULL` (breakdown per rule for explainability — feeds UI "why at risk")
- `status RISK_STATUS(OPEN, ASSESSED, EXPIRED) NOT NULL DEFAULT 'OPEN'`
- `computed_at TIMESTAMPTZ NOT NULL`, `expires_at TIMESTAMPTZ`
- Index `(status, score DESC)` per spec; `(tenant_id, subject_type, subject_id)`

**recovery_cases**
- `id UUID PK`, `tenant_id`, `case_number INT NOT NULL` UNIQUE `(tenant_id, case_number)` (displayed as RC-{number})
- `customer_id FK NOT NULL`, `risk_id FK→revenue_risks NULL`
- `risk_type RISK_TYPE NOT NULL`
- `source_entity_type TEXT NOT NULL`, `source_entity_id UUID NOT NULL`
- `amount_at_risk BIGINT NOT NULL CHECK (>0)`, `currency CHAR(3) NOT NULL`
- `risk_score INT NOT NULL` (snapshot at open)
- `status CASE_STATUS enum NOT NULL DEFAULT 'DETECTED'` (domain s-03 values)
- `status_reason TEXT NULL`, `stop_conditions MET stop list TEXT[] DEFAULT '{}'`
- `assigned_to UUID FK→users NULL`
- `workflow_id UUID NULL` (set when Temporal starts; FK to workflows row)
- `attribution_window_hours INT NOT NULL DEFAULT 72`
- `opened_at TIMESTAMPTZ NOT NULL DEFAULT now()`, `closed_at TIMESTAMPTZ NULL`, `updated_at`
- **Partial unique index**: `(tenant_id, source_entity_type, source_entity_id)` WHERE status NOT IN ('RECOVERED','STOPPED','FAILED') ← one live case per obligation
- Indexes: `(status, opened_at)` per spec, `(customer_id)` per spec, `(tenant_id, status)`

**ai_decisions**
- `id UUID PK`, `tenant_id`, `case_id FK NOT NULL`
- `model TEXT NOT NULL`, `model_version TEXT`, `prompt_version TEXT NOT NULL`
- `input_snapshot JSONB NOT NULL` (redacted context actually sent)
- `output_raw JSONB NULL` (validated structured output as returned)
- `diagnosis_cause TEXT NULL`, `diagnosis_confidence NUMERIC(3,2) NULL CHECK (0..1)`
- `recommended_actions JSONB NOT NULL` (array of catalog actions w/ params)
- `stop_conditions TEXT[] NOT NULL DEFAULT '{}'`
- `status DECISION_STATUS(COMPLETED, INVALID_OUTPUT, FALLBACK_RULE_BASED, FAILED, POLICY_REJECTED) NOT NULL`
- `latency_ms INT`, `input_tokens INT`, `output_tokens INT`, `cost_minor_units BIGINT NOT NULL DEFAULT 0`
- `error TEXT NULL`, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- Index `(case_id, created_at DESC)`

**recovery_actions**
- `id UUID PK`, `tenant_id`, `case_id FK NOT NULL`
- `decision_id FK→ai_decisions NULL` (null ⇒ system/manual origin)
- `type ACTION_TYPE enum NOT NULL` (catalog s-03)
- `parameters JSONB NOT NULL` (validated against catalog schema)
- `status ACTION_STATUS(PROPOSED, APPROVAL_REQUIRED, APPROVED, POLICY_REJECTED, EXECUTING, EXECUTED, FAILED, CANCELLED, SKIPPED) NOT NULL DEFAULT 'PROPOSED'`
- `policy_result JSONB NULL` (evaluation summary snapshot)
- `attempt_number INT NOT NULL DEFAULT 1`
- `idempotency_key TEXT NOT NULL UNIQUE` = `{tenant}:{case}:{TYPE}:{attempt_number}` (spec 01 §21)
- `scheduled_at TIMESTAMPTZ`, `started_at`, `completed_at TIMESTAMPTZ`, `result JSONB NULL`, `error JSONB NULL`
- Index `(case_id, created_at)` per spec

**workflows**
- `id UUID PK`, `tenant_id`, `case_id FK NOT NULL UNIQUE` (one workflow row per case lifecycle)
- `temporal_workflow_id TEXT NOT NULL UNIQUE` (= `recover:{case_id}`), `run_id TEXT`
- `type TEXT NOT NULL` ('FailedPaymentRecoveryWorkflow'|…)
- `status WF_STATUS(RUNNING, COMPLETED, FAILED, CANCELLED, CONTINUED_AS_NEW) NOT NULL DEFAULT 'RUNNING'`
- `started_at`, `closed_at`

**workflow_events** (append-only mirror of significant workflow progress for offline querying)
- `id BIGSERIAL PK`, `workflow_row_id FK NOT NULL ON DELETE CASCADE`, `type TEXT`, `payload JSONB`, `occurred_at`; index `(workflow_row_id, occurred_at)`

**messages**
- `id UUID PK`, `tenant_id`, `case_id FK NULL`, `customer_id FK NOT NULL`
- `channel CHANNEL enum NOT NULL`, `direction enum(OUTBOUND, INBOUND) NOT NULL DEFAULT 'OUTBOUND'`
- `template_id TEXT NOT NULL`, `variables JSONB NOT NULL DEFAULT '{}'` (redacted per allowlist)
- `to_address TEXT NOT NULL` (email or phone)
- `provider MESSAGING_PROVIDER(WHATSAPP_CLOUD, SMTP_EMAIL, MOCK) NOT NULL`
- `provider_message_id TEXT NULL`
- `idempotency_key TEXT NOT NULL UNIQUE` = `{tenant}:{case}:{channel}:{template}:{step}` 
- `status MESSAGE_STATUS(QUEUED, SENT, DELIVERED, READ, FAILED, BOUNCED, REJECTED) NOT NULL DEFAULT 'QUEUED'`
- `sent_at TIMESTAMPTZ`, `final_status_at TIMESTAMPTZ`
- Index `(case_id, created_at)`; `(customer_id, channel, sent_at DESC)` ← powers contact-frequency policies

**message_delivery_events** (append-only webhook/status callbacks)
- `id BIGSERIAL PK`, `message_id FK`, `status MESSAGE_STATUS`, `payload JSONB`, `occurred_at`

**customer_responses**
- `id UUID PK`, `tenant_id`, `customer_id FK NOT NULL`, `case_id FK NULL`
- `channel CHANNEL`, `type RESPONSE_TYPE(REPLY, OPT_OUT, PROMISE_TO_PAY, COMPLAINT, OTHER) NOT NULL`
- `content_redacted TEXT NULL`, `raw_ref TEXT NULL` (pointer to storage if kept), `received_at TIMESTAMPTZ NOT NULL`
- Index `(customer_id, received_at DESC)`, `(case_id)`

**promises_to_pay**
- `id UUID PK`, `tenant_id`, `case_id FK NOT NULL`
- `promised_amount BIGINT NOT NULL`, `currency CHAR(3)`
- `promised_by_date DATE NOT NULL`, `status PTP_STATUS(MADE, HONORED, BROKEN, EXPIRED) NOT NULL DEFAULT 'MADE'`
- `honored_payment_id UUID FK→payments NULL`, `created_at`, `resolved_at`

**human_tasks**
- `id UUID PK`, `tenant_id`, `case_id FK NOT NULL`
- `type TASK_TYPE(APPROVAL, DISPUTE_REVIEW, COMPLIANCE_REVIEW, WORKFLOW_FAILURE, GENERAL) NOT NULL`
- `title TEXT NOT NULL`, `description TEXT`, `priority enum(LOW, MEDIUM, HIGH, URGENT) DEFAULT 'MEDIUM'`
- `status HT_STATUS(PENDING, ASSIGNED, APPROVED, REJECTED, RESOLVED, CANCELLED) NOT NULL DEFAULT 'PENDING'`
- `assigned_to UUID FK→users NULL`, `sla_due_at TIMESTAMPTZ`
- `decided_by UUID FK→users NULL`, `decision_notes TEXT`, `decided_at TIMESTAMPTZ`
- `temporal_signal_sent BOOLEAN NOT NULL DEFAULT false` (links approval back into workflow wait)
- Index `(status, sla_due_at)`, `(case_id)`

**policy_rules**
- `id UUID PK`, `tenant_id FK NULL` (NULL = platform default seeded rule)
- `code TEXT NOT NULL UNIQUE` (e.g., MAX_PAYMENT_RETRIES), `name TEXT NOT NULL`, `description TEXT`
- `rule_kind RULE_KIND(REJECT, REQUIRE_APPROVAL, LIMIT) NOT NULL`
- `definition JSONB NOT NULL` (structured condition: field path/op/value + applies_to action types)
- `enabled BOOLEAN NOT NULL DEFAULT true`, `created_at`, `updated_at`

**policy_versions** (immutable snapshots)
- `id UUID PK`, `rule_id FK NOT NULL`, `version INT NOT NULL` UNIQUE `(rule_id, version)`
- `snapshot JSONB NOT NULL`, `created_by UUID NULL`, `created_at`

**policy_evaluations** (append-only — every evaluation auditable)
- `id UUID PK`, `tenant_id`, `case_id FK NULL`, `decision_id FK NULL`
- `rule_versions UUID[] NOT NULL` (which versions were in force)
- `result POLICY_RESULT(ALLOWED, REJECTED, REQUIRE_APPROVAL) NOT NULL`
- `rejections JSONB NOT NULL DEFAULT '[]'`, `effective_actions JSONB NOT NULL`
- `latency_ms INT NOT NULL`, `evaluated_at TIMESTAMPTZ NOT NULL DEFAULT now()`

**audit_logs** (append-only, compliance-oriented)
- `id BIGSERIAL PK`, `tenant_id FK NOT NULL`, `case_id UUID NULL`
- `actor_type ACTOR_TYPE NOT NULL`, `actor_id TEXT NULL`
- `event TEXT NOT NULL`, `metadata JSONB NOT NULL DEFAULT '{}'`
  - metadata keys per spec 01 §18: model, model_version, prompt_version, decision, policy_version, action, result
- `correlation_id UUID NULL`, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- Index `(case_id, created_at)` per spec; `(tenant_id, created_at DESC)`
- No updated_at column by design.

**case_events** (append-only timeline feed powering the dashboard case view)
- `id BIGSERIAL PK`, `tenant_id`, `case_id FK NOT NULL`
- `event_type CASE_EVENT_TYPE TEXT NOT NULL` (vocabulary from s-03)
- `actor_type ACTOR_TYPE NOT NULL`, `actor_id TEXT NULL`
- `description TEXT`, `payload JSONB DEFAULT '{}'`, `occurred_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- Index `(case_id, occurred_at)` 

**recovery_outcomes** (authoritative economics — analytics never derives from UI state, spec 01 §25)
- `id UUID PK`, `tenant_id`, `case_id FK NOT NULL UNIQUE` (one final outcome per case)
- `payment_id FK→payments NOT NULL`
- `baseline_amount BIGINT NOT NULL` (= amount_at_risk at open)
- `recovered_amount BIGINT NOT NULL`, `recovery_cost BIGINT NOT NULL DEFAULT 0`
- `net_recovered BIGINT GENERATED ALWAYS AS (recovered_amount - recovery_cost) STORED`
- `attribution_method TEXT NOT NULL` ('WORKFLOW_LINKED' | 'ATTRIBUTION_WINDOW')
- `attribution_window_hours INT NOT NULL`, `recovered_at TIMESTAMPTZ NOT NULL`, `recorded_at DEFAULT now()`

**recovery_cost_entries** (append-only ledger feeding recovery_cost)
- `id UUID PK`, `tenant_id`, `case_id FK NOT NULL`
- `category COST_CATEGORY(LLM, MESSAGING, PAYMENT_PROCESSING, DISCOUNT, MANUAL_HANDLING, PROVIDER) NOT NULL`
- `amount BIGINT NOT NULL` (minor units), `currency CHAR(3)`, `metadata JSONB`, `incurred_at TIMESTAMPTZ NOT NULL`
- Index `(case_id, category)`

**idempotency_keys** (generic store for non-action HTTP idempotency, e.g., POST /events)
- `key TEXT PK` (scoped, e.g., `evt:{source}:{external_id}` or caller-supplied Idempotency-Key)
- `request_hash TEXT NOT NULL`, `response_snapshot JSONB NULL`, `status PROCESSING|COMPLETED|FAILED`
- `locked_until TIMESTAMPTZ NULL` (lease), `created_at`, `expires_at TIMESTAMPTZ NOT NULL`

### Transaction & concurrency notes to encode in schema comments

- Case creation + risk attach happen in ONE transaction guarded by the partial unique index.
- Action execution uses conditional UPDATE `WHERE status IN ('APPROVED')` returning rowCount to claim EXECUTING atomically.
- Outcome insert conflicts on unique(case_id) must be treated as already-finalized (no double count).

## Reliability

Summary of the five anti-duplication anchors introduced here (call out in code review checklist):

```text
1. events (source, external_event_id)      → no duplicate ingestion
2. recovery_cases partial unique            → one live case per obligation
3. recovery_actions.idempotency_key UNIQUE  → no double financial action
4. messages.idempotency_key UNIQUE          → no duplicate customer contact
5. recovery_outcomes.case_id UNIQUE         → recovered amount counted once
```

Plus `idempotency_keys` lease column for request-level idempotency of async endpoints.

## Security Considerations

- `messages.variables` and `content_redacted` must contain only allowlisted fields (enforced by writer services, verified by tests in s-19/s-30).
- `audit_logs` gets restricted DB role later (s-30): INSERT+SELECT only for app role; no UPDATE/DELETE grants ever.
