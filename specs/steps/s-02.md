# Step 02 — Local Infrastructure & Configuration Platform

## Objective

Stand up the complete local infrastructure (PostgreSQL, Redis, Temporal + Temporal UI, Redpanda + console) via Docker Compose with health checks, and build the typed configuration package that every app/service uses to load and validate environment variables. After this step, `docker compose up -d` produces a working dependency stack and every workspace can read validated config from `@repo/config`.

## Why this step exists

Every later step (DB migrations s-04+, Temporal workflows s-20+, event bus s-11+) assumes running infrastructure and a reliable config source. The repo's `.env.example` already declares the required variables (`DATABASE_URL`, `DIRECT_URL`, `REDIS_URL`, `TEMPORAL_ADDRESS`, `REDPANDA_BROKERS`, `LLM_API_KEY`, `AI_MODEL`, Stripe/Razorpay, WhatsApp/Email) — this step makes those variables *enforced* rather than optional strings scattered across `process.env` reads.

## Requirements

1. `infra/docker/docker-compose.yml` with services: `postgres`, `redis`, `temporal`, `temporal-ui`, `redpanda`, `redpanda-console`, `frontend` — all with health checks and named volumes.
2. Temporal local server configured via `infra/temporal/dynamicconfig.yaml` (namespace auto-create enabled).
3. `packages/config` — typed, validated environment loading using zod; per-workspace presets (`apiConfig()`, `workerConfig()`, `webConfig()`); fail-fast on missing/invalid values.
4. Extend root `.env.example` with any newly introduced variables (e.g., `EVENT_BUS_DRIVER=redpanda|inprocess`, `MOCK_PROVIDERS=true|false`, failure-injection switches from spec 03 §9: `SIMULATE_PAYMENT_TIMEOUT`, `SIMULATE_MESSAGE_FAILURE`, `SIMULATE_LLM_FAILURE`, `SIMULATE_DUPLICATE_WEBHOOK`, plus `LOG_LEVEL`, `OTEL_EXPORTER_OTLP_ENDPOINT`).
5. Root-level convenience scripts (`bun run infra:up`, `infra:down`) in root `package.json`.
6. Verify `packages/db/src/migrate.ts` runs successfully against the composed Postgres (creates `_drizzle_migrations`; no tables yet).

## Technical Implementation

### Compose services & ports

```text
postgres         localhost:5432   (db: revenue_recovery, user: postgres/postgres)  healthcheck: pg_isready
redis            localhost:6379                                                    healthcheck: redis-cli ping
temporal         localhost:7233   (temporalio/auto-setup)                           depends_on: postgres healthy
temporal-ui      localhost:8080   (temporalio/ui)                                   depends_on: temporal
redpanda         localhost:9092   (redpandadata/redpanda)                           healthcheck: rpk cluster health
redpanda-console localhost:8081   (redpandadata/console)
frontend         localhost:3000   (apps/frontend/Dockerfile standalone)             healthcheck: wget http://127.0.0.1:3000/
```

Temporal auto-setup requires its own internal DB — use the `TEMPORAL_POSTGRES_SEEDS`/bundled approach of `temporalio/auto-setup` pointing at the composed postgres with separate databases (`temporal`, `temporal_visibility`). Document this in compose comments.

### packages/config design

```text
packages/config/
├── src/
│   ├── env.ts          # raw zod schemas per group
│   ├── api.ts          # apiConfig()
│   ├── worker.ts       # workerConfig()
│   └── index.ts
```

Config groups (all validated, typed, exported as frozen objects):

- `app`: NODE_ENV enum(dev,test,production), PORT (default 8000), LOG_LEVEL
- `database`: DATABASE_URL, DIRECT_URL
- `redis`: REDIS_URL
- `temporal`: TEMPORAL_ADDRESS, TEMPORAL_NAMESPACE (default `revenue-recovery`)
- `bus`: EVENT_BUS_DRIVER enum(`redpanda`,`inprocess`, default `inprocess`), REDPANDA_BROKERS
- `ai`: LLM_API_KEY, AI_MODEL (default `gpt-4o`), LLM_BASE_URL (optional override), LLM_TIMEOUT_MS (default 20000), LLM_MAX_RETRIES (default 2)
- `payments`: STRIPE_SECRET_KEY?, STRIPE_WEBHOOK_SECRET?, RAZORPAY_KEY_ID?, RAZORPAY_KEY_SECRET?, RAZORPAY_WEBHOOK_SECRET?
- `messaging`: WHATSAPP_API_KEY?, WHATSAPP_PHONE_NUMBER_ID?, EMAIL_API_KEY?, EMAIL_FROM?
- `demo`: MOCK_PROVIDERS boolean (default true in dev), SIMULATE_* booleans (default false)
- `otel`: OTEL_EXPORTER_OTLP_ENDPOINT?

Rule: provider credentials are **nullable** at startup when `MOCK_PROVIDERS=true`; required otherwise (refinement in schema). This enables spec 03 §2 mock mode.

## Reliability

- Health checks gate dependent containers so a cold `docker compose up -d` converges without manual ordering.
- Config is immutable after boot; no runtime re-reads (prevents inconsistent state mid-request).
