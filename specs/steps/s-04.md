# Step 04 — Database Schema: Financial Core Entities

## Objective

Implement the Drizzle schema for tenants, users, API keys, customers, payments, payment attempts, subscriptions, checkouts, checkout events, invoices, and invoice events — with all enums, constraints, unique keys, and the indexes mandated by spec 01 §5. Generate and apply the first SQL migration.

## Why this step exists

PostgreSQL is the source of truth (spec 02 §1). The financial core is what recovery operates on: without canonical payment/checkout/invoice records there is nothing to detect risk on or recover. This step also establishes tenant-scoping patterns every later table copies.

## Requirement Coverage

- Spec 01 §5 PostgreSQL schema list (customers, payments, payment_attempts, subscriptions, checkouts, checkout_events, invoices, invoice_events) + required indexes
- Spec 02 §15 tenant isolation (tenant_id on every business table)
- Spec 03 §4 demo data model fields
- Spec 03 §11 "Tenant context mandatory"

## Prerequisites

- s-03 (`@repo/domain` enums are the single source for Postgres enum values)

## Requirements

1. Schema files under `packages/db/src/schema/` split by aggregate; `index.ts` re-exports all.
2. Every business table carries `tenant_id`, `created_at`, `updated_at` (audit fields).
3. Money columns: `amount BIGINT NOT NULL` minor units + `currency CHAR(3) NOT NULL`.
4. Soft delete: only on `customers` (deleted_at); financial records are immutable history — corrections happen via compensating events, never UPDATE of amounts.
5. Generate migration via drizzle-kit and apply with `bun run db:migrate`.

## Technical Implementation

### File layout

```text
packages/db/src/schema/
├── index.ts            # barrel export
├── _shared.ts          # timestamps helper, tenant column helper, money helper
├── enums.ts            # pgEnum(...) definitions mirroring @repo/domain
├── tenants.ts
├── users.ts            # incl. api_keys
├── customers.ts
├── payments.ts         # incl. payment_attempts
├── subscriptions.ts
├── checkouts.ts        # incl. checkout_events

```

### Tables

**tenants**
- `id UUID PK DEFAULT gen_random_uuid()`
- `name TEXT NOT NULL`, `slug TEXT NOT NULL UNIQUE`
- `status enum(TENANT_STATUS: ACTIVE, SUSPENDED) NOT NULL DEFAULT 'ACTIVE'`
- `settings JSONB NOT NULL DEFAULT '{}'` (attribution window hours, timezone, contact prefs defaults)
- `created_at/updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`

**users**
- `id UUID PK`, `tenant_id UUID FK→tenants ON DELETE RESTRICT NOT NULL`
- `email CITEXT NOT NULL`, `name TEXT NOT NULL`
- `role USER_ROLE enum(ADMIN, FINANCE, OPERATIONS, SUPPORT, VIEWER) NOT NULL`
- `password_hash TEXT` (nullable until first login provisioned), `status enum(ACTIVE, DISABLED)`
- `last_login_at TIMESTAMPTZ`
- UNIQUE `(tenant_id, email)`; index `tenant_id`

**api_keys**
- `id UUID PK`, `tenant_id FK NOT NULL`, `name TEXT NOT NULL`
- `key_hash TEXT NOT NULL UNIQUE` (sha256 of bearer token; raw key shown once at creation)
- `scopes TEXT[] NOT NULL DEFAULT '{events:write}'`
- `revoked_at TIMESTAMPTZ NULL`, `last_used_at TIMESTAMPTZ`, `created_by UUID FK→users`

**customers**
- `id UUID PK`, `tenant_id FK NOT NULL`
- `external_ref TEXT` (provider-side customer id, nullable for internal-only customers)
- `name TEXT NOT NULL`, `email CITEXT`, `phone TEXT`
- `status enum(ACTIVE, CHURNED, BLOCKED) NOT NULL DEFAULT 'ACTIVE'`
- `lifetime_value BIGINT NOT NULL DEFAULT 0`
- `opted_out BOOLEAN NOT NULL DEFAULT false`, `opted_out_at TIMESTAMPTZ`  ← drives policy rule "no outbound after opt-out" (spec 02 §7)
- `metadata JSONB NOT NULL DEFAULT '{}'`
- `deleted_at TIMESTAMPTZ NULL` (soft delete)
- UNIQUE `(tenant_id, external_ref)` where external_ref not null; indexes `(tenant_id, email)`, `(tenant_id, phone)`

**payments**
- `id UUID PK`, `tenant_id FK NOT NULL`, `customer_id FK→customers NOT NULL`
- `subscription_id UUID FK→subscriptions NULL`
- `amount BIGINT NOT NULL CHECK (amount > 0)`, `currency CHAR(3) NOT NULL`
- `status PAYMENT_STATUS enum NOT NULL DEFAULT 'CREATED'`
- `provider PROVIDER enum(STRIPE, RAZORPAY, MOCK) NOT NULL`
- `provider_payment_id TEXT NOT NULL` — UNIQUE `(tenant_id, provider, provider_payment_id)` ← webhook dedup anchor
- `failure_code TEXT NULL`, `failure_message TEXT NULL`
- `method_metadata JSONB NOT NULL DEFAULT '{}'` (card network, last4 only — never PAN)
- `occurred_at TIMESTAMPTZ NOT NULL`, `paid_at/refunded_at/disputed_at TIMESTAMPTZ NULL`
- Indexes per spec: `(customer_id, created_at)`, `(status, created_at)`; plus `(tenant_id, occurred_at)`

**payment_attempts**
- `id UUID PK`, `tenant_id`, `payment_id FK NOT NULL`
- `attempt_number INT NOT NULL` — UNIQUE `(payment_id, attempt_number)`
- `initiated_by enum(PROVIDER_AUTO, RECOVERY_WORKFLOW, MANUAL) NOT NULL`
- `idempotency_key TEXT NOT NULL UNIQUE` ← format `{tenant_id}:{case_id}:RETRY_PAYMENT:{attempt}` (spec 01 §21)
- `status enum(REQUESTED, SUCCEEDED, FAILED, UNKNOWN) NOT NULL`
- `provider_reference TEXT`, `failure_code TEXT`, `error JSONB`
- `requested_at TIMESTAMPTZ NOT NULL`, `resolved_at TIMESTAMPTZ`

**subscriptions**
- `id UUID PK`, `tenant_id`, `customer_id FK NOT NULL`
- `plan_name TEXT`, `amount BIGINT NOT NULL`, `currency CHAR(3)`
- `status SUBSCRIPTION_STATUS enum(ACTIVE, PAST_DUE, PAUSED, CANCELLED, INCOMPLETE) NOT NULL DEFAULT 'ACTIVE'`
- `provider PROVIDER NOT NULL`, `provider_subscription_id TEXT NOT NULL` — UNIQUE `(tenant_id, provider, provider_subscription_id)`
- `current_period_start/end TIMESTAMPTZ`, `cancelled_at TIMESTAMPTZ`
- Index `(customer_id, status)`

**checkouts**
- `id UUID PK`, `tenant_id`, `customer_id FK NOT NULL`
- `cart_value BIGINT NOT NULL DEFAULT 0`, `currency CHAR(3) NOT NULL`
- `items JSONB NOT NULL DEFAULT '[]'` (sku/name/qty/unit_amount only)
- `status CHECKOUT_STATUS enum NOT NULL DEFAULT 'STARTED'`
- `source_ref TEXT` (e.g., Shopify cart token / Stripe Checkout session id) UNIQUE `(tenant_id, source_ref)` when present
- `started_at TIMESTAMPTZ NOT NULL`, `last_activity_at TIMESTAMPTZ NOT NULL`, `completed_at`, `abandoned_at`, `expires_at`
- Index `(status, last_activity_at)` per spec; `(tenant_id, customer_id, status)`

**checkout_events** (append-only)
- `id BIGSERIAL PK`, `checkout_id FK NOT NULL ON DELETE CASCADE`
- `type TEXT NOT NULL` (checkout.started | item_added | payment_started | completed | abandoned | expired)
- `payload JSONB NOT NULL DEFAULT '{}'`, `occurred_at TIMESTAMPTZ NOT NULL`
- Index `(checkout_id, occurred_at)`

**invoices**
- `id UUID PK`, `tenant_id`, `customer_id FK NOT NULL`
- `number TEXT NOT NULL` UNIQUE `(tenant_id, number)`
- `amount BIGINT NOT NULL`, `amount_paid BIGINT NOT NULL DEFAULT 0`, `currency CHAR(3)`
- `status INVOICE_STATUS enum NOT NULL DEFAULT 'DRAFT'`
- `issued_at TIMESTAMPTZ`, `due_at TIMESTAMPTZ NOT NULL`, `paid_at TIMESTAMPTZ`, `disputed_at TIMESTAMPTZ`
- `provider PROVIDER NULL`, `provider_invoice_id TEXT NULL` — UNIQUE `(tenant_id, provider, provider_invoice_id)` when present
- Index `(status, due_at)` per spec; `(tenant_id, customer_id, status)`

**invoice_events** (append-only) — same shape as checkout_events with `invoice_id`.

## Reliability

- UNIQUE anchors chosen deliberately: `(tenant_id, provider, provider_payment_id)` kills duplicate-webhook upserts; `payment_attempts.idempotency_key` kills duplicate retries; `(payment_id, attempt_number)` kills concurrent attempt-number races.
- All FKs `ON DELETE RESTRICT` except child event tables (`CASCADE`). Financial history must never be silently deleted.
- `updated_at` maintained by Drizzle `$onUpdate` — document that optimistic concurrency uses explicit `WHERE updated_at = ?` guards in repositories where needed.

## Security Considerations

- No column anywhere stores card numbers, CVV, tokens-as-PAN, or bank credentials. Only provider references.
- `api_keys.key_hash` — SHA-256 hash; raw keys never persisted.
- `users.password_hash` — argon2id (hashing introduced with auth in s-09).
