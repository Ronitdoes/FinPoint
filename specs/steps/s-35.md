# Step 35 — Final Hardening, Demo Readiness & Release

## Objective

Execute the final pre-release pass: full requirement-coverage re-audit against the four spec documents, code-quality sweep (dead code, TODO burn-down, boundary lint audit), complete demo narrative rehearsal per spec 01 §27, presentation checklist execution from spec 03 §12, and the formal MVP Definition-of-Done sign-off (spec 01 §29 + spec 03 §1 matrix).

## Why this step exists

Every prior step optimized its own scope; releases fail on the seams. Spec 01 §27 defines a precise 3–5 minute, nine-scene demo; §29 an eighteen-point DoD; spec 03 §12 a thirteen-item presentation checklist. This step converts "features exist" into "the system is demonstrable, auditable, and signed off," and freezes v0.1.0.

## Requirement Coverage

- Spec 01 §27 demo narrative (9 scenes) — rehearsed & scripted
- Spec 01 §29 definition of done (18 items) — final gate
- Spec 03 §12 presentation checklist
- Spec 03 §1 feature matrix final verification
- Spec 00 Phase-1 scope closure (everything listed shipped or explicitly deferred with pointer)

## Prerequisites

- s-01…s-34 all complete

## Requirements

1. Coverage re-audit: regenerate TRACEABILITY.md from actual code/tests; every row links implementation + test evidence; gaps become either fix-now items or documented deferrals (ML scoring, voice, multi-agent, experimentation — Phase 2+ per spec 00 §10).
2. Quality sweep:
   - zero TODO/FIXME without linked issue
   - boundary lint audit report (no AI→adapters paths, no provider creds outside integrations, no raw SQL outside repositories)
   - type coverage: `strict` green everywhere incl. frontend
   - bundle/size sanity for frontend (initial route JS budget <300KB gz)
3. Documentation finalization: root README rewrite (what it is, architecture diagram reference, quickstart = clone→compose→seed→demo in ≤10 commands), docs index, ADR index.
4. Demo readiness:
   - `docs/demo-script.md` finalized: exact commands/clicks/timings for 9 scenes incl. expected numbers on screen (₹12.8L at risk → ₹12,999 recovered delta etc.)
   - dry-run ×3 by someone who didn't build it; friction log resolved
   - fallback plan if live LLM unavailable during demo (injection toggle → fallback-mode narrative prepared)
5. Release mechanics: version tag v0.1.0 across workspaces; changelog generated; images promoted staging→prod registry; prod deploy executed via pipeline; post-deploy smoke + alert silence check.
6. Sign-off artifact: docs/RELEASE-v0.1.0.md containing completed §29 checklist (each item ✓ + evidence link), §12 checklist ticks, known-limitations list (honesty section), and deferral register.
